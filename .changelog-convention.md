# Keep a Changelog convention notes

Fuurin no Class follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) and [Semantic Versioning](https://semver.org/).

Future additions to `CHANGELOG.md` should follow this structure:

```markdown
## [<version>] — <YYYY-MM-DD> — <title>

### Added
### Changed
### Deprecated
### Removed
### Fixed
### Security
```

- Group changes by category inside each release.
- One release per published version.
- `Unreleased` is the working section for the next version.
- Always include the version comparison link footer at the bottom:

```markdown
[Unreleased]: https://github.com/<org>/<repo>/compare/v<X.Y.Z>...HEAD
[X.Y.Z]: https://github.com/<org>/<repo>/compare/v<A.B.C>...v<X.Y.Z>
```
